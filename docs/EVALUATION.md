## 1. 지금 구조에서 바로 뽑을 수 있는 정량 지표

라벨(전문가 태깅)이 없어도(`PROJECT.md` R4) 계산 가능한 것부터 정리한다. "필요한 것" 열이
`없음`이면 오늘 바로 실행 가능하다는 뜻이다.

### 1.1 지표 엔진 자체의 내적 정합성 (V1 확장)

| # | 지표 | 방법 | 필요한 것 |
| --- | --- | --- | --- |

### 1.3 카메라 각도 일관성 (V2, 하네스는 이미 구현됨)

`eval/harness.py`의 `angle_consistency()`는 이미 완성·검증돼 있다(`tests/unit/test_eval_harness.py`).
**막힌 건 코드가 아니라 데이터** — 동일 동작을 정면/45°/측면에서 동시 촬영한 영상이 없다
(`PROGRESS.md` §4.2). 이 영상만 있으면 오늘 바로:

```python
results = [pos01(pose_front, target), pos01(pose_45deg, target), pos01(pose_side, target)]
consistency = angle_consistency(results)  # mean_std, max_std, coverage
```

로 ADR-0001 §5의 헤드라인 숫자(각도 간 표준편차)가 나온다. `samples/metrics_demo.py`가
이 흐름을 **합성 노이즈로만** 시연한다 — 진짜 카메라 강건성 결과는 아니다.

### 1.4 대조군 테이크 (V3) — 촬영만 하면 라벨링 거의 불필요

같은 사람이 "일부러 무너진 자세" 테이크와 "평소 자세" 테이크를 각 30초씩 찍으면:

- 두 그룹 간 POS-01/POS-03/AXI-01 평균 차이의 **효과크기(Cohen's d)**
- Mann-Whitney U 검정 p-value (정규성 가정 없이)

를 계산할 수 있다. 촬영자 본인이 "이건 무너진 테이크"라고 아는 것 자체가 라벨이므로
전문가 라벨링(V4, 20~30클립 필요)보다 훨씬 싸게 `PROJECT.md` SC-2("좋은 테이크/나쁜
테이크를 지표가 유의하게 구분")의 1차 증거를 만들 수 있다.

### 1.5 향후 (V4/V5, 전문가 라벨 필요)

- Finding vs 사람 태깅 구간의 IoU/precision/recall, Cohen's kappa
- 라벨 상관 기반 임계값 재보정 후 ROC/PR 커브

## 2. 오픈 데이터셋으로 지금 구조를 테스트하기

**아르헨티나 탱고, 특히 클로즈 엠브레이스 커플 댄스 데이터셋은 사실상 존재하지 않는다.**
아래는 전체 도메인(탱고 코칭 임계값)을 대체하는 게 아니라, **파이프라인의 개별
컴포넌트**(검출/포즈/중력정렬/추적/발 관절)를 탱고 영상 없이 미리 검증하기 위한
후보들이다. 최종 임계값 캘리브레이션(V4/V5)은 여전히 사용자 본인 영상 + 전문가 라벨이
필요하다 — 이건 그 전 단계의 "부품 테스트"용.

| 데이터셋 | 무엇을 검증하는가 | 이 구조와의 연결점 | 접근/라이선스 메모 |
| --- | --- | --- | --- |
| **Halpe / COCO-WholeBody** | 발 관절(heel/foot_index) 포함 2D 포즈 정확도 | ADR-0001 §2 C1이 요구하는 Tier A 교체(COCO-17 → Halpe-26)의 **직접 검증 데이터** — AXI-01/05가 필요로 하는 발 관절 자체의 정확도를 처음 잴 수 있음 | Halpe: SJTU 공개, 비상업 연구용. COCO-WholeBody: COCO 라이선스 상속 |
| **AIST++ (Google, AIST Dance DB의 3D 확장)** | 9대 동기화 카메라 + SMPL 3D 라벨 | ADR-0001 §5 M2 벤치마크가 요구하는 "동일 동작 다각도 동시촬영"을 **실제 데이터로 대체** — `eval.harness.angle_consistency()`를 처음으로 진짜 영상에 돌려볼 수 있는 가장 현실적인 후보. 탱고는 아니고 대부분 솔로 스트리트 댄스라 커플/엠브레이스 검증에는 안 맞음 | `google/aistplusplus_api`(GitHub), 연구용 — 음악·안무 저작권은 원 소유자에게 있어 상업적 재사용 전 확인 필요 |
| **3DPW (3D Poses in the Wild)** | 실외, IMU 기반 글로벌 궤적, 단안 입력 | world-grounded 백엔드 후보(GVHMR/NLF) 벤치마크, 카메라 틸트 강건성(R3) 검증 | 연구용 라이선스, 등록 필요 |
| **EMDB** | EM 센서 기반 진짜 글로벌 궤적 GT, 야외 | `geometry/gravity.py` 폴백 체인의 정확도를 잴 수 있는 몇 안 되는 "진짜 중력/월드 프레임 GT"가 있는 데이터셋 | 연구용, GitHub 공개 |
| **Human3.6M** | 실내 멀티뷰 고전 벤치마크 | POS 계열 각도 정확도 기본 검증 (발 관절 없어 AXI 계열엔 부적합 — C1과 같은 이유) | 등록 필요, 비상업 |
| **CHI3D / Hi4D / FlickrCI3D Signatures** (BUDDI 논문이 쓰는 데이터셋군, `scripts/two_person_axis.py` docstring에서 이미 언급) | 두 사람이 실제로 접촉/포옹하는 3D 데이터, 일부는 접촉 라벨 포함 | **M4(커플 확장) + C3(클로즈 엠브레이스에서 top-down 추정 붕괴) 문제의 가장 가까운 오픈 대체재.** 접촉 라벨은 CPL-02(아브라소 높이 일관성) 실험에도 쓸 수 있음 | 각각 별도 라이선스, 대부분 비상업 연구용 — 사용 전 개별 확인 |
| **CrowdHuman** | 사람이 심하게 겹친 상황의 검출(박스만, 포즈 없음) | RT-DETRv2가 겹친 두 사람을 박스 두 개로 분리하는지(C3 완화 이전 단계) recall/precision 정량화 — 지금 `perception/detect/rtdetr.py`에 단위 테스트가 0개라는 격차(§1.1 #4)를 메우는 데 바로 쓸 수 있음 | CC BY-SA 4.0, 상업 사용 가능 |
| **MOT17 / MOT20** | 다중 인물 추적 표준 벤치마크(MOTA, IDF1, ID switch count) | M4의 `perception/track/`이 구현되면 R6(ID 스와핑)를 표준 지표로 정량화 | 연구용 |
| **DanceTrack** | 댄스 배틀 영상 기반 MOT 벤치마크, 빠른 교차/유사 외형 상황 | 커플은 아니지만 "빠르게 교차·겹치는 사람들 사이에서 ID를 유지하는가"라는 성격이 탱고의 회전/교차와 비슷 — ReID 임베딩(ADR-0001 C4-2, DINOv2) 실험용 참고 벤치마크 | 연구용, GitHub 공개 |

### 권장 순서 (효용 대비 비용)

1. **Halpe/COCO-WholeBody** — 가장 싸고, ADR-0001의 미해결 항목(D3: Halpe-26 기반
   DVI-Canonical 확정)을 실제로 종결시킬 수 있는 데이터
2. **AIST++** — `eval/harness.py`를 실제 데이터로 처음 돌려보는 가장 현실적인 경로.
   ADR-0001 §5 M2 벤치마크가 몇 세션째 "동시 다각도 촬영 영상 없음"으로 막혀 있는
   것(`PROGRESS.md` §4.2)의 임시 우회로가 된다
3. **CHI3D/Hi4D/FlickrCI3D** — `PROGRESS.md` §6이 재확인한 "다음 자연스러운
   작업"(M4, 검출·추적·클로즈 엠브레이스 대응)에 직접 연결됨
4. **CrowdHuman** — `perception/detect/`의 테스트 커버리지 0을 메우는 가장 직접적인 방법
5. **3DPW/EMDB** — Tier B/C 백엔드 벤치마크(§4.2)가 실제로 진행될 때
6. **MOT17/MOT20/DanceTrack** — Track 스테이지 구현 착수 시점에

어느 것도 아르헨티나 탱고 자체는 아니므로, 이 데이터셋들로 얻는 결론은 항상
**"이 컴포넌트가 일반적으로 잘 동작하는가"**까지다. "탱고에서 좋은 축이란 무엇인가"라는
질문의 답(코칭 임계값, `configs/styles/*.yaml`의 현재 값들)은 여전히 사용자 본인의
영상과 전문가 라벨(V4/V5)에서만 나온다.
